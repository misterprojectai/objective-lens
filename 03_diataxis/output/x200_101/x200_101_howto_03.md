# How to Identify and Modify $PATH for Command Availability

This guide shows you how to inspect the current `$PATH`, add a directory for the current session, and persist that change so it survives a new login shell.

---

## Before You Begin

Ensure you have:

- An interactive Bash shell as a regular user (not root)
- A directory you need to add to `$PATH` — either an existing one such as `/opt/myapp/bin` or a custom directory you have already created

---

## Steps

### 1. Inspect the Current $PATH

Display the current search path:

```bash
echo $PATH
```

To read each directory on its own line:

```bash
echo $PATH | tr ':' '\n'
```

Note the order — the shell searches directories left to right and stops at the first match.

---

### 2. Check Whether Your Directory Is Already in $PATH

Search for the target directory before making any change:

```bash
echo $PATH | tr ':' '\n' | grep '/opt/myapp/bin'
```

If the command returns no output, the directory is not in `$PATH` and must be added.

---

### 3. Add the Directory for the Current Session

If you want the directory searched first (takes priority over existing commands with the same name), prepend it:

```bash
export PATH=/opt/myapp/bin:$PATH
```

If you want the directory searched last (existing commands take priority), append it:

```bash
export PATH=$PATH:/opt/myapp/bin
```

> **Note:** This change applies to the current shell session and any child processes only. It is lost when the session ends.

---

### 4. Persist the Change in ~/.bash_profile

Open `~/.bash_profile` in a text editor and add the export line at the end of the file:

```bash
echo 'export PATH=/opt/myapp/bin:$PATH' >> ~/.bash_profile
```

Use single quotes so that `$PATH` is written literally into the file — the shell will expand it at login time, not now.

---

### 5. Verify the Change Survives a New Login Shell

Force Bash to re-read the login profile without logging out:

```bash
bash --login -c 'echo $PATH | tr ":" "\n"'
```

Confirm that `/opt/myapp/bin` appears in the output, then open a full new login shell to test the real-world case:

```bash
exec bash --login
echo $PATH | tr ':' '\n'
```

---

## Verification

Confirm the directory is present and in the expected position:

```bash
echo $PATH | tr ':' '\n' | grep -n '/opt/myapp/bin'
```

Expected result: the line number shown reflects the priority position — a low number means early in the search order (prepended), a high number means late (appended).

Confirm a command in the added directory is now found:

```bash
type mycommand
```

Expected result: `mycommand is /opt/myapp/bin/mycommand`

---

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| Command still not found after adding directory | Directory not saved correctly or typo in path | Run `echo $PATH \| tr ':' '\n'` and confirm the exact path appears |
| Change lost after opening a new terminal | Export was added to `~/.bashrc` instead of `~/.bash_profile`, or terminal opens a non-login shell | Verify the export line is in `~/.bash_profile`; for non-login interactive shells, also add it to `~/.bashrc` |
| New login shell does not pick up the change | `~/.bash_profile` was not saved, or the file has a syntax error that aborted loading | Run `bash --login -c 'echo loaded'`; if it fails silently, check `~/.bash_profile` for syntax errors with `bash -n ~/.bash_profile` |
| Prepended directory is still searched after `/usr/bin` | `$PATH` was not included in the export — the old value was discarded | Ensure the export contains `$PATH`: `export PATH=/opt/myapp/bin:$PATH`, not `export PATH=/opt/myapp/bin` |
| Permission denied running a command in the added directory | The binary is not executable | Run `chmod +x /opt/myapp/bin/mycommand` to add execute permission |
