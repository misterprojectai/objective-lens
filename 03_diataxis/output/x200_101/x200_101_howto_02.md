# How to Diagnose and Fix a 'command not found' Error

This guide shows you how to identify whether a `command not found` error results from a `$PATH` problem, an uninstalled package, a typo, or a missing executable permission, and apply the correct fix.

---

## Before You Begin

Ensure you have:

- A Bash shell prompt on an RHEL system
- Sufficient privileges to install packages with `dnf` if the package is missing (root or sudo access)

---

## Steps

### 1. Check for a Typo Using `type`

Run `type` against the command name you attempted.

```bash
type tpye
```

If the shell returns:

```
bash: type: tpye: not found
```

compare the spelling against the known correct command name. Re-run with the corrected spelling.

---

### 2. Confirm What `type` Reports for a Valid Command

Run `type` against the intended command to determine how the shell classifies it.

```bash
type ls
```

Expected results and what they mean:

- `ls is aliased to 'ls --color=auto'` — command is an alias; it should work
- `ls is /usr/bin/ls` — command is an external executable; it should work
- `ls is a shell builtin` — command is built into Bash; it will always work
- `bash: type: ls: not found` — command is not found by any resolution method; continue to Step 3

---

### 3. Inspect `$PATH` for Missing Directories

Print the current `$PATH` to check whether expected directories are present.

```bash
echo $PATH
```

A healthy RHEL user `$PATH` looks like:

```
/home/student/.local/bin:/home/student/bin:/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin
```

If `/usr/bin` or `/usr/sbin` is absent from the output, your `$PATH` has been corrupted or overwritten. Restore the default for this session:

```bash
export PATH=/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:$HOME/.local/bin:$HOME/bin
```

Re-run the original command. If it succeeds, the problem was a broken `$PATH`.

---

### 4. Use `which` to Locate the Executable on Disk

If `$PATH` looks correct but the command is still not found, use `which` to search `$PATH` directories explicitly.

```bash
which git
```

If `which` returns no output or a `no git in (...)` message, the executable does not exist anywhere in `$PATH`. Proceed to Step 5.

If `which` returns a path such as `/usr/bin/git`, the executable exists. Proceed to Step 6 to check permissions.

---

### 5. Check Whether the Package Is Installed

Search for the package that provides the missing command.

```bash
dnf provides git
```

If the output shows an available package, install it:

```bash
sudo dnf install -y git
```

Re-run the original command after installation completes.

If you know the binary path but want to identify its package, use:

```bash
dnf provides /usr/bin/git
```

---

### 6. Check Executable Permission on the File

If `which` found the file but the shell still refuses to run it, inspect the file's permissions.

```bash
ls -l /usr/bin/git
```

Look at the permission bits in the first column. The file needs an `x` bit for the appropriate user class:

```
-rwxr-xr-x. 1 root root 3941240 Jan 15 12:00 /usr/bin/git
```

If the execute bit is missing (for example, `-rw-r--r--`), restore it:

```bash
sudo chmod +x /usr/bin/git
```

---

## Verification

Confirm the command now resolves correctly:

```bash
type git
```

The response identifies the command as an external executable at a path under `/usr/bin` or `/usr/local/bin`. Running the command itself completes without a `command not found` error.

---

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| `type` returns `not found` even after correcting the spelling | Command is not installed and not on `$PATH` | Run `dnf provides <command>` and install the package |
| `/usr/bin` is absent from `echo $PATH` output | `$PATH` was overwritten in the current session | Run `export PATH=/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:$HOME/.local/bin:$HOME/bin` |
| `which` finds the file but running it still fails with `Permission denied` | Execute bit is missing from the file | Run `sudo chmod +x <full-path-to-file>` |
| Command works as root but not as a regular user | `/usr/sbin` is in root's `$PATH` but not the user's | Run the command with `sudo`, or add `/usr/sbin` to the user's `$PATH` |
| `dnf provides` returns no match | Package name differs from the command name | Run `dnf search <keyword>` to locate the correct package name |
