# How to Capture an Intermediate Pipeline Stage to a File While Continuing Processing

This guide shows you how to insert `tee` at a chosen stage in a pipeline to snapshot the data stream to a file without breaking the pipeline.

---

## Before You Begin

Ensure you have:

- A terminal session on a RHEL 9 system where you can write to `/tmp` or your home directory
- A pipeline you need to debug or audit at a specific intermediate stage — `tee` is only useful when at least one more command follows it

---

## Steps

### 1. Identify the pipeline stage to capture

Choose the command whose output you want to preserve. `tee` reads from stdin and writes simultaneously to stdout and to a file — insert it immediately after the command whose output you need.

A three-stage pipeline without capture:

```bash
ps aux | grep -v grep | awk '{print $1}' | sort -u
```

---

### 2. Insert tee after the target command

Place `tee` after the command whose output you want to snapshot, passing the destination filename as its argument. Data continues flowing to the next command unchanged.

```bash
ps aux | grep -v grep | tee /tmp/ps_snapshot.txt | awk '{print $1}' | sort -u
```

The terminal shows the final pipeline output. `/tmp/ps_snapshot.txt` receives the stream exactly as it existed after `grep -v grep`, before `awk` transformed it.

---

### 3. Append to an existing file instead of overwriting it

If the file already contains data you want to keep, use `tee -a`:

```bash
ps aux | grep -v grep | tee -a /tmp/ps_snapshot.txt | awk '{print $1}' | sort -u
```

Without `-a`, each pipeline run overwrites the file from the previous run.

---

### 4. Capture multiple intermediate stages simultaneously

Insert additional `tee` calls at each stage you want to record:

```bash
cat /etc/passwd | tee /tmp/stage1_raw.txt | grep '/bin/bash' | tee /tmp/stage2_bash_users.txt | cut -d: -f1 | sort
```

`/tmp/stage1_raw.txt` receives the full file content. `/tmp/stage2_bash_users.txt` receives only the bash-user lines. The terminal shows the final sorted usernames.

---

### 5. Suppress terminal output when you only want the file

If the downstream command is the terminal and you want `tee` to write to a file without displaying data on screen, pipe the final output to `/dev/null`:

```bash
ps aux | grep -v grep | tee /tmp/ps_snapshot.txt > /dev/null
```

> **Note:** This pattern is only appropriate when the file is the sole desired output. Do not use it when commands follow `tee` in the pipeline.

---

### 6. Capture a stage while also passing stderr through the pipeline

By default, `tee` only handles stdout. If the upstream command can produce errors and you want them captured at the same snapshot point, redirect stderr into stdout before `tee`:

```bash
find /etc -name "*.conf" 2>&1 | tee /tmp/find_snapshot.txt | grep -c 'Permission denied'
```

The snapshot file contains both normal results and permission errors. The terminal shows only the count of permission-denied lines.

---

## Verification

Confirm the snapshot file was written and the pipeline continued processing:

```bash
wc -l /tmp/ps_snapshot.txt
```

The line count must be greater than zero and must match the number of lines produced by the upstream command, not the final pipeline output.

To confirm the pipeline result is independent of the file, compare:

```bash
ps aux | grep -v grep | awk '{print $1}' | sort -u | wc -l
wc -l /tmp/ps_snapshot.txt
```

The counts will differ — the snapshot count is larger because it precedes `awk` and `sort -u` filtering.

---

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| `/tmp/ps_snapshot.txt` is empty after the pipeline runs | The upstream command produced no output — a filter like `grep` eliminated everything | Remove `tee` temporarily and run the pipeline up to that stage to confirm upstream output exists |
| File content from a previous run is missing | `tee` without `-a` overwrites on each run | Use `tee -a` to append, or choose a uniquely named file per run (e.g., append a timestamp with `$(date +%s)`) |
| Terminal shows no output but the file was written | `tee` output was redirected to `/dev/null` unintentionally — check for `> /dev/null` after `tee` | Remove `> /dev/null` if downstream processing is needed, or pipe to the next command instead |
| stderr messages appear on screen but not in the snapshot file | `tee` only captures stdout; stderr bypasses it by default | Merge streams with `2>&1` before `tee`, or redirect stderr separately with `2> errors.txt` |
| The snapshot file contains the final output, not the intermediate stage | `tee` was inserted after the last command instead of the target intermediate command | Move `tee` to immediately after the command whose output you need to capture |
| Pipeline hangs after inserting `tee` | The command after `tee` is not consuming stdin — it does not read from a pipe | Verify the downstream command accepts stdin; replace it with `cat` temporarily to confirm data is flowing |
