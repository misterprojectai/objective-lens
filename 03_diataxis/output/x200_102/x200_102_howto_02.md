# How to Append Output to a Log File Across Repeated Command Runs

This guide shows you how to accumulate output from multiple command invocations into a single persistent log file using `>>`.

---

## Before You Begin

Ensure you have:

- Write permission to the directory where the log file will be created
- A log file path decided in advance — this guide uses `~/command.log` throughout

---

## Steps

### 1. Create the log file with the first command run

Redirect the first command's output into the log file using `>>`. If the file does not exist, `>>` creates it. If it does exist, output is added to the end.

```bash
date >> ~/command.log
```

### 2. Append output from a second command run

Run the same command again, or a different command, using `>>` to the same file.

```bash
date >> ~/command.log
```

### 3. Append output from a third command

Continue appending as many times as needed. Each invocation adds to the end of the file without disturbing earlier content.

```bash
uptime >> ~/command.log
```

### 4. Append from a command with arguments

Any command that produces stdout works with `>>`. Use the full command as you would normally, followed by `>> logfile`.

```bash
df -h >> ~/command.log
```

### 5. Append a separator line between runs

When logging across multiple invocations, insert a blank line or timestamp separator to make entries distinguishable.

```bash
echo "---" >> ~/command.log
```

---

## Verification

Confirm that all runs accumulated into one file without overwriting earlier entries:

```bash
cat ~/command.log
```

The file contains output from every command run in sequence — no earlier entry is missing or overwritten.

To confirm line count grew with each append, run `wc -l ~/command.log` before and after a new append and verify the count increases.

---

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| Log file contains only the most recent run's output | Used `>` instead of `>>` — each run overwrote the file | Replace `>` with `>>` in the command |
| `>>` reports `Permission denied` | The log file or its directory is not writable by the current user | Write to a path you own, such as `~/` or `/tmp/` |
| Log file is empty after running the command | The command produced no stdout — it may have written to stderr instead | Append stderr with `2>> ~/command.log` or combine streams with `>> ~/command.log 2>&1` |
| Entries from different runs run together with no separation | No separator was appended between invocations | Add `echo "---" >> ~/command.log` or `date >> ~/command.log` between runs |
