# How to Capture Command Output to a File for Later Inspection

This guide shows you how to save the stdout of any command to a named file without displaying it on the terminal.

---

## Before You Begin

Ensure you have:

- Write permission to the directory where you intend to create the file
- The command whose output you want to capture available on your system

---

## Steps

### 1. Redirect stdout to a new file

Run the command followed by `>` and the target filename.

```bash
command > /path/to/outputfile.txt
```

No output appears on the terminal. The shell creates the file if it does not exist and overwrites it if it does.

> **Note:** `>` silently overwrites an existing file with no prompt or warning.

---

### 2. Choose the right operator for your situation

If you want to **create or overwrite** the file each time:

```bash
ls -lh /etc > ~/etc_listing.txt
```

If you want to **append** to an existing file rather than overwrite it:

```bash
ls -lh /var >> ~/etc_listing.txt
```

---

### 3. Redirect stdout while suppressing terminal display

For any command, the pattern is identical — the command name changes, the redirection syntax does not.

```bash
df -h > ~/disk_report.txt
```

```bash
ps aux > ~/process_snapshot.txt
```

---

### 4. Append a timestamp header before the command output

Add a timestamp line first, then append the command output below it.

```bash
date >> ~/disk_report.txt
df -h >> ~/disk_report.txt
```

---

## Verification

Confirm the file was created and contains output:

```bash
ls -lh ~/disk_report.txt
cat ~/disk_report.txt
```

Expected result: `ls` reports a non-zero file size and `cat` displays the saved output.

---

## Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| `bash: /path/to/file: Permission denied` | You do not have write permission to the target directory | Use a path you own, such as `~/filename.txt`, or check permissions with `ls -ld /target/dir` |
| Output file is empty | The command produced no stdout — only stderr, or no output at all | Run the command without redirection first to confirm it generates output |
| Existing file content was lost | `>` overwrites without warning | Use `>>` to append, or check the file before redirecting with `ls -lh filename` |
| Output appears on terminal instead of going to the file | A typo placed the `>` before the command name, or the shell misread the operator | Verify the syntax: `command > file`, not `> command file` |
